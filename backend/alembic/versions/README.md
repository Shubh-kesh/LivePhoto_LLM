# Migration workflow

- Migration files (revisions) live in this directory.
- M1 intentionally ships **no business migration**: no schema exists yet, and M1 forbids creating
  fake tables just to produce a migration.
- Generate a migration from the backend directory once business models exist:

  ```bash
  uv run alembic revision --autogenerate -m "describe change"
  ```

- Review every autogenerated migration by hand before committing. The metadata naming convention
  (`app/db/base.py`) keeps constraint/index names deterministic and within MSSQL's 128-character
  identifier limit.
- Run migrations against a configured database (requires `DATABASE_URL`):

  ```bash
  uv run alembic upgrade head
  ```

  Migrations are never run against the production database without review and approval.
- Unit tests do not require MSSQL; database integration tests (later) use `TEST_DATABASE_URL` and
  are skipped with a clear reason when no integration database is available.
