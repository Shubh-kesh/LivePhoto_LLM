# LivePhoto M5.8 — Manual Postman / local flow

These steps validate the M5.8 flow locally. No real D365 verification is claimed.

## Prerequisites

1. Backend: `uv run uvicorn app.main:app --reload` (from `backend/`).
2. Frontend: `npm run dev` (from `frontend/`; Vite proxies `/api` and `/xbiz/live_photo/l`).
3. Consumer config: `cp config/consumers.example.json config/consumers.local.json` (from `backend/`),
   then set in `consumers.local.json`: `active: true`, `callback.auth_type: "none"`,
   `callback.url: "http://localhost:3001/livephoto/callback"`,
   `allowed_redirect_origins: ["http://localhost:3001"]`.
4. Optional stub consumer: `node frontend/e2e/stub-consumer.mjs` (returns redirect_url on :3001).
5. Backend `.env`: `S2S_AUTH_MODE=local_dev`, `S2S_LOCAL_DEV_TOKEN=<local>`,
   `PUBLIC_LIVEPHOTO_BASE_URL=http://localhost:5173`,
   `CONSUMER_PROFILES_PATH=backend/config/consumers.local.json`,
   `DECISION_TEST_WRITER_ENABLED=true`, `PORTRAIT_PROCESSING_ENABLED=true`.

## Steps

1. **POST launch session** (Postman):
   `POST http://localhost:8000/api/v1/integration/launch-sessions`
   Headers: `X-LivePhoto-Dev-Auth: <local>`, `Content-Type: application/json`
   Body: `{"transaction_id":"test0906t","source":"D365","ocr_required":false,"camera_config":"1","white_background":true,"output_file_format":"jpeg"}`
2. Copy `launch_url` from the response.
3. Open the `launch_url` in Chrome/Edge.
4. Verify the URL becomes clean (`/xbiz/live_photo/`).
5. Capture a photo (open camera, capture).
6. (Dev PASS seam, only if `DECISION_TEST_WRITER_ENABLED=true` locally) prepare the portrait; the
   page calls the dev PASS writer + portrait.
7. Preview the processed portrait.
8. Submit; verify the stub consumer receives the callback and the browser redirects to
   `http://localhost:3001/complete`.
9. Query the status API:
   `GET http://localhost:8000/api/v1/integration/transactions/test0906t/status?source=D365`
   (header `X-LivePhoto-Dev-Auth`). Expect `status: "COMPLETED"`.
10. Reopen a completed launch URL -> completed terminal UI; capture is blocked.
11. Test an invalid/expired token -> "Link unavailable".

Do not use real banking credentials; local-dev auth and the dev PASS writer exist only in
local/test/development.
