# LivePhoto — M5 VLM Baseline Results

Status: M5 baseline. **Real-provider smoke complete; accuracy baseline NOT MEASURED** (dataset
gate blocked).

## Real-provider smoke (executed)

One approved non-sensitive synthetic image was submitted to the configured real provider.

| Provider | Exact model | Images | Classification | Structured-output validity | Latency |
|---|---|---|---|---|---|
| Gemini | `gemini-3.8-flash` | 1 (`single-quality-v1`) | `QUALITY_FAILURE` | valid (JSON parsed into `vlm-result-v1`) | ~2585 ms |
| Gemini | `gemini-3.8-flash` | 3 (`temporal-triad-v1`) | `QUALITY_FAILURE` | valid | ~2930 ms |

The blank synthetic frame produced `QUALITY_FAILURE` (reasonable). During the smoke, real Gemini
emitted evidence codes outside the controlled enum (`BLANK_FRAME`, `SOLID_COLOR`); the adapter was
updated to retain unknown codes as observations while keeping `classification`/`attack_medium`
strict (documented in `VLM_PROVIDER_ARCHITECTURE.md`). Connectivity, authentication and structured
output are therefore verified for Gemini.

**Provider availability ≠ accuracy (M5 §150).** These smoke calls prove integration only.

## What will be reported once unblocked

Track A (**PUBLIC DATASET VLM BASELINE**) and Track B (**LIVEPHOTO NATIVE CAPTURE BASELINE**) are
kept separate (M5 §46). Reports will include: per-class spoof→LIVE (numerator/denominator),
APCER-style + Wilson 95% CI, BPCER-style, genuine non-accept, uncertain/conclusive rates,
provider-reliability (timeouts/429/auth/schema), confidence buckets with spoof→LIVE,
high-confidence errors, single-vs-triad paired comparison, latency percentiles, repeatability,
prompt-injection subset, border-visibility analysis, and an evidence-based M6 priority analysis —
all generated by `app/experiments/vlm/` (see `docs/VLM_BASELINE_EVALUATION.md`).

## Manual checklist for the user (device + dataset gates)

1. Laptop: Chrome/Safari → `/capture` → permission → preview → real MediaPipe face guidance →
   8-frame burst → quality evaluation → selected frame → retake → cleanup. Record OS/browser/
   browser version/camera resolution.
2. Mobile (Android Chrome or iPhone Safari): same flow; front camera; rear + switch where present;
   portrait + landscape.
3. Dataset: obtain license/EULA approval or collect consented POC captures (see
   `docs/M5_DATASET_BOOTSTRAP.md`); place under `local-data/`; run
   `python -m app.experiments.vlm.datasets.bootstrap`-style tooling or provide a manifest; then
   run the benchmark with `--live --max-requests N`.
